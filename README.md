# Raven61 Web Driver

Raven61 홀 이펙트 키보드용 브라우저 기반 설정 도구입니다. WebHID로 보드에 직접 붙기
때문에 설치가 필요 없고, 순정 윈도우 드라이버 없이 크롬/엣지에서 바로 동작합니다.

> **브랜치:** 이 `dev` 브랜치는 **작업 중인 전부**입니다 — 리버스 엔지니어링 도구,
> 분석 스크립트, 아직 프로토콜이 해독되지 않은 설정 패널까지 포함합니다.
> `main` 은 완성되어 실제로 동작하는 것만 담습니다 (장치 연결 + 모니터).
> 기능이 완성되면 `dev` 에서 `main` 으로 올립니다.
> `main` 은 <https://sufl3770.github.io/Raven61WebDriver/> 에 자동 배포됩니다.
> 이 브랜치는 배포되지 않으므로 로컬에서 실행해야 합니다.

> **현재 상태:** **읽기는 하드웨어에서 검증 완료** — 입력 지점 탭이 61키 전부의 현재
> 설정을 보드에서 읽어 표시합니다. **액추에이션 포인트 쓰기는 하드웨어에서 확인
> 완료**, **래피드 트리거 쓰기도 붙었습니다** — 활성 · 민감도(누름/뗌) · 전체 스트로크
> 퀵 트리거 · 데드존은 키별 레코드로, "바닥까지 트리거"는 전역 블록으로 나갑니다.
> 어느 쪽이든 읽기-수정-쓰기로 보내고 쓴 뒤 다시 읽어 바이트를 대조합니다.
>
> 순정 드라이버 분석과 하드웨어로 확인된 것:
>
> - 장치 **VID `0x19F5`**, PID `FE20` / `FED0` / `FEB1`, USB 인터페이스 `MI_01`
> - 통신은 **OUTPUT / INPUT 리포트** (`WriteFile` / `ReadFile`), 65바이트, 리포트 ID 0
> - **패킷 프레임**: 매직 `0x55`, 명령, 합 체크섬. 쓰기 응답은 에코(`0xaa`),
>   **읽기 응답은 데이터를 실어 옵니다**
> - **송수신 헬퍼가 둘** — 읽기 명령은 전부 두 번째 쪽입니다 (§1.1)
> - **블록 전송**: 길이 + 오프셋(LE16) + 56바이트 청크. 읽기도 동일
> - **읽기 명령**: `0x05` 전역 설정 · `0x07` 키맵 · `0xa0` 키별 성능 · `0xde` RGB
> - **플래시 설정 영역 지도 전체 (§3.8)** — 명령 31개가 각각 어느 블록을 다루는지
>   펌웨어에서 확정했습니다. `0x07` 은 **공장 기본** 키맵이고 실사용 키맵은 `0x08`,
>   `0x0a` 는 키맵이 아니라 **키별 RGB**, 그리고 `0xa3` · `0xa5` · `0xa7` 은
>   셋 다 조명이 아니라 **고급키**입니다 (한 기능이 세 표에 나뉘어 있습니다)
> - **키별 성능 블록** 완전 해독 — 1024 B, 키당 8바이트. 동작 지점 · RT 활성 ·
>   RT 민감도 · 전체 스트로크 퀵 트리거 · 데드존 · 스위치 종류 (§4.5)
> - **쓰기(`0xa1`) 절차** 해독 — `0x01`, 56바이트 청크 19개, `0x02` (§4.5.5).
>   순정은 버퍼를 0으로 밀고 만들지만 이 앱은 읽기-수정-쓰기로 갑니다 (§4.5.6)
> - **전역 설정 쓰기(`0x06`)** — 순정도 `0x05` 응답을 복사해 고쳐 보냅니다 (§4.8.1).
>   이전 판의 "필드가 독립적이다" 는 근거 없는 서술이었고, 그 위에 만든
>   `enableAnalogReport` 가 폴링 레이트·데드존을 0으로 덮고 있었습니다
> - **필드 한계는 접힘이지 실패가 아니다** — 데드존 5비트(0.62 mm), 민감도·동작 지점
>   9비트. 인코더가 포화시키고 UI 상한도 같은 값을 씁니다 (§4.5)
> - **키 주소는 "슬롯"** — 계산할 수 없고 키맵 블록에서 받아야 합니다 (§4.6).
>   XML 의 `key_index` 는 순정도 쓰지 않는 사문이었습니다 (§6)
> - **`switch_type` 8종**과 스위치별 총 스트로크 — 총 스트로크는 4 mm 고정이 아닙니다 (§4.7)
> - **아날로그 키 이벤트** 완전 해독 — 61키 전부 식별, 실시간 모니터가 동작합니다
> - **보정 표를 펌웨어에서 읽어냈습니다 (§3.3)** — 키별 8바이트, 플래시 `0x20300`,
>   **`0xaa` 로 통째로 읽힙니다**. 실체는 float32 **보정 계수** 하나이고, 깊이 보고가
>   전부 이 값을 거칩니다. 이벤트에도 매번 실려 옵니다 — `payload[10]` 이 LED 색을
>   정하는 상태 바이트, `payload[11..13]` 이 계수의 10진 세 자리입니다
> - ⚠ **보드의 LED 는 보정 품질을 나타내지 않습니다** — 그 상태 바이트는 계수가 몇 번
>   커졌는지 센 값이라 펌웨어 업데이트 직후엔 멀쩡한 키까지 전부 빨강이고, 얕게 두 번만
>   눌러도 초록이 됩니다. 이 앱은 **계수**로 판정하고 보드의 판정은 나란히 보여 주기만
>   합니다 (§3.3)
> - 이 결론 전까지 이 프로젝트는 순정 드라이버만 보고 "판정 = ADC 진폭 누적 최댓값" 이라고
>   적고 있었습니다. **틀렸습니다** — 순정은 계산하지 않고 펌웨어가 준 바이트를 옮길
>   뿐입니다 (findings.md 오류 #19)
> - 스트림은 **켜야 흐릅니다** — `0xa8` 이 보고를 켜고(걸쇠) 동시에 테스트 모드에
>   들어가므로, 바로 `0xa9` 로 모드만 빠져나오면 **깊이 수신 + 타이핑 정상**입니다.
>   `0xa8` 을 **반복**하면 모드가 유지되어 캘리브레이션이 됩니다 (§3.2)
> - 값 인코딩 **1 카운트 = 0.02 mm**. 와이어는 **−1 오프셋**으로 저장
> - 설정 데이터 모델, 레이어 4개, 프로파일 3개, 고급 키 6종 (순정 DB 기준)
> - **보드에는 프로파일이 없습니다 (§7.1)** — 펌웨어에 2프로파일 구조가 있지만 이
>   모델은 레이어 2장(기본 + Fn) 분량의 플래시만 할당돼 있고, 전환되는 것도
>   **키맵뿐**입니다. RT·조명·매크로는 전역 1벌입니다. 같은 프로토콜의 프로파일 지원
>   모델 대응은 §7.2 에 틀만 잡아 두었습니다
> - **키맵 레코드와 순정 리맵 목록을 값까지 해독했습니다 (§7.3)** — 레코드는
>   `[타입][param][code]` 3바이트이고, 순정 인코더(`0x429f80`)의 분기가 곧 리맵 탭이
>   만들 수 있는 전부입니다. 컨슈머 usage · 마우스 마스크 · 조명 동작 코드까지 값이
>   나와 있고, 레이어 읽기(`0x08`)와 쓰기(`0x09`, 레이어당 10청크)를 **하드웨어에서
>   확인했습니다**
> - ⚠ **`0xee` 는 공장 초기화**입니다. 스윕에 넣지 마세요 (§3)
>
> 자세한 내용은 [docs/protocol.md](docs/protocol.md), 무엇이 틀렸었는지는
> [docs/findings.md](docs/findings.md).

## 실행

```bash
npm install
npm run dev
```

크롬, 엣지, 오페라 **데스크톱** 에서 열어야 합니다 (WebHID 필요). 파이어폭스와 사파리는
WebHID를 지원하지 않습니다.

## 데모 모드

키보드가 없어도 연결 화면의 **데모 모드로 둘러보기** 를 누르면 전체 UI를 그대로 쓸 수
있습니다. 패널을 흉내 낸 화면이 아니라 **보드를 흉내 낸 것** 입니다 — `src/demo/` 가
64바이트 출력 리포트를 받아 입력 리포트로 답하는 가짜 HID 장치라, 그 위의 코덱 선택 ·
블록 청크 읽기 · 읽기-수정-쓰기 · 쓴 뒤 되읽어 대조하는 절차가 하드웨어에서와 똑같이
돕니다.

- 보드는 **87키 ANSI 텐키리스** 입니다 (`src/demo/layout.ts`). 60% 는 홀 이펙트
  보드로서는 흥미롭지만 앱을 보여 주기엔 나쁜 선택입니다 — 없는 키를 일일이 설명해야
  하니까요. TKL 은 F열 · 편집 클러스터 · 방향키가 있을 자리에 있습니다. 프로토콜은
  Raven61 에서 해독한 그대로이고, 다른 것은 키 수에서 따라오는 두 가지뿐입니다:
  보정 표가 64칸이 아니라 128칸이고, 슬롯에 구멍이 없습니다.
- 실시간 깊이는 **지금 치고 있는 키보드** 를 보고합니다. `KeyboardEvent.code` 를 HID
  usage 로 옮겨 그 키의 스트로크를 그립니다 (`src/demo/keys.ts`).
- 캘리브레이션도 동작합니다. 테스트 모드(`0xa8` 유지)에서 키를 바닥까지 누르면 펌웨어와
  같은 규칙으로 보정 계수가 자라고 상태 바이트가 올라갑니다.
- 공장 초기화는 **보정 표를 남깁니다** — 실제 펌웨어의 초기화 루틴이 `0x20300` 을 건드리지
  않는 것과 같습니다.
- `navigator.hid` 를 쓰지 않으므로 **파이어폭스·사파리에서도 열립니다**.

보드의 블롭 값은 캡처가 아니라 그럴듯하게 지어낸 것입니다. 화면에 보이는 숫자를 실제
하드웨어의 근거로 읽으면 안 됩니다 — 그건 `docs/protocol.md` 쪽입니다.

## 탭 구성

**첫 화면** — 장치가 붙기 전에는 연결 화면 하나뿐입니다. 나머지 탭은 전부 보드를
들여다보는 화면이라, 연결된 뒤에 나타납니다. 연결은 VID 0x19F5 프리셋으로 고르고
점수가 가장 높은 인터페이스를 자동으로 엽니다. 한 번 허용한 장치는 브라우저가
기억하므로 다음부턴 버튼 하나로 다시 붙습니다.

**설정 패널** — 입력 지점(읽기 + 쓰기) · 센서(모니터) · 캘리브레이션 · 키 매핑 ·
라이트(효과 + 키별 색)가 하드웨어에서 동작합니다. **고급 키와 매크로는 프로토콜을
해독하고 읽기·쓰기를 붙였지만 아직 하드웨어에서 확인되지 않았습니다** — 패널이 그렇게
적어 둡니다. 조명의 뮤직 레이어는 여전히 미해독이라 잠겨 있습니다.

| 탭 | 내용 |
|----|------|
| 입력 지점 | **동작** — 61키 전부의 현재 설정(동작 지점·RT·민감도·전체 스트로크·스위치 종류)을 보드에서 읽어 표시하고, **스위치 종류 · 동작 지점 · 래피드 트리거 · 데드존 · 바닥까지 트리거를 보드에 씁니다**. 쓴 뒤 다시 읽어 대조하고, 직전 1024바이트로 되돌릴 수 있습니다. 원본 블록 덤프 포함 |
| 센서 | **동작** — 실시간 키 깊이, 트레이스, 키별 원시 ADC |
| 키 매핑 | **동작** — 입력 지점과 같은 격자에서 키 하나를 고르고(매핑을 정하면 다음 키로 자동 이동) 레이어 2장(기본 · FN 1)의 현재 매핑을 보드에서 읽고(`0x08`), 순정 리맵 탭과 같은 목록에서 골라 씁니다(`0x09`) — 기본 키는 104키 풀배열 그림, 나머지는 기호 · 멀티미디어 · 특수 키 · 기능 · 조명 · 마우스 · 매크로. 수정자 조합, 선택 키 공장값 복원 포함. 매크로 분류는 저장소를 직접 읽어 `canonical` 이 아니면 잠깁니다 (§5.5). 디버그 모드에서는 usage · 레코드 직접 입력 분류가 하나 더 붙습니다. 고급키는 **고급 키 탭**이 씁니다 (§7.3) |
| 고급 키 | **해독 완료 · 하드웨어 미검증** — DKS · TGL · MT · RS · SOCD · OKS 여섯 종류 전부입니다. 세 표(`0xa2`/`0xa3` DKS 24바이트, `0xa4`/`0xa5` MT·RS·SOCD·OKS 6바이트, `0xa6`/`0xa7` TGL 3바이트)를 읽어 키맵 두 장을 훑고 어느 캡이 어느 레코드를 부르는지 보여줍니다. 격자에서 키를 고르고 종류를 정한 뒤, **레코드를 먼저 쓰고 키맵을 나중에** 씁니다 — 그 사이 보드에는 아무도 가리키지 않는 레코드가 있을 뿐이지만, 반대 순서라면 아직 쓰지 않은 레코드를 키가 가리킵니다. 쓰기마다 되읽어 대조합니다 (§5) |
| 라이트 | **동작** — 두 구역입니다. **효과**: 효과 23종을 이름으로 고르고 밝기(0–100 %) · 속도(0–4) · 방향 · 여러 색 순환 · 색상을 씁니다(전역 블록 `payload[16..24]`, `0x05`→`0x06` 읽기-수정-쓰기 · 되읽어 대조). 효과마다 순정과 같은 기준(`config_func`)으로 **그 효과가 쓰는 컨트롤만** 보여주고, 미해독인 `colorindex` 는 보드 값을 그대로 되씁니다. 순정은 이 값들을 자기 DB 에서 읽지만 이 앱은 **보드에서 읽습니다** (§4.8.2). **키별 색**: 커스텀 색을 읽어(`0x0a`) 캡에 칠하고 격자에서 칠해 씁니다(`0x0b`) — 이 색을 보여주는 효과는 **커스텀 조명**(모드 0) 하나뿐이라 그 자리에서 바로 전환할 수 있습니다. **지금 표시 중**(`0xde`)은 순정처럼 프레임을 계속 다시 읽어(순정은 작업 큐가 빌 때마다, 이 앱은 100 ms 상한) **어떤 키의 LED 가 지금 켜져 있는지 실시간으로** 보여줍니다 — 효과와 보정 오버레이가 얹힌 RAM 버퍼라 저장된 층과 다른 것이 정상입니다. 남은 미해독은 뮤직 레이어입니다 — `0x224f0`·`0x225f0` 은 조명이 아니라 고급키 표였습니다 (§3.8) |
| 매크로 | **해독 완료 · 하드웨어 미검증** — **32칸** 저장소(`0x0c`/`0x0d`, 4 KB `0x21100`)입니다. 순정은 10칸만 관리하지만 그것은 순정의 한계입니다(자기 DB 를 쓰고 이 블록을 되읽지 않습니다) — 재생기는 31번 칸까지 받으므로 이 앱은 32칸을 쓰고, 화면에는 기본 10칸 · **디버그 모드에서 32칸**을 내놓습니다. 순정의 `M 1` 이 여기의 `#0` 입니다. 한 칸의 본문은 `[지연 u16][제어][값]` 4바이트 레코드의 나열이고, 제어가 정지·누름/뗌·종류(수정자 마스크 / HID usage)를 담습니다. 지연은 **밀리초**입니다(TIM3 프리스케일 143 · 주기 1000). 타이핑을 그대로 **녹화**하거나(키 사이 간격을 지연으로 적습니다) 키를 하나씩 넣고, 목록 반복·지연 일괄 적용으로 다듬은 뒤 저장소를 쓰고 격자에서 키에 붙입니다. **저장소 먼저, 키맵 나중**이고 대조에 실패하면 키맵은 나가지 않습니다. ⚠ 재생기에 커서 상한이 없어서 **0 으로 초기화된 저장소에 매크로 키를 붙이면 보드가 플래시를 훑으며 타이핑합니다** — 그래서 이 앱은 **32칸 전부**를 정지 레코드까지 새로 깔고, 그 전에는 바인딩을 거부합니다. 순정 저장소에서 **빈 칸은 다음 본문의 오프셋을 그대로 가집니다** — 그런 칸은 빈 칸으로 읽고 주인을 알려 주며, 마지막 본문 뒤를 가리키는 칸은 **전부 0 인 레코드**에서 멈춥니다. 반복 횟수 바이트는 펌웨어가 읽지 않아 읽기 전용입니다. 이름은 보드에 자리가 없어 브라우저에만 남습니다. 형식은 순정 프로필 내보내기에 든 실제 녹화와 순정 인코더로 **한 필드씩 대조했습니다** (§5.5) |
| 설정 | **동작** — 펌웨어 빌드 정보, 폴링 레이트·디바운스 읽기·쓰기, 공장 초기화(⚠ 확인 2단계) |

**디버그 모드** — **Shift 를 5번 빠르게** 누르면 켜지고, 같은 동작으로 꺼집니다. 화면에
버튼은 없습니다 — 프로토콜을 해독할 때 말고는 쓸 일이 없는 기능이라 눈에 보이는 자리를
차지하지 않게 했습니다. 켜짐 여부는 `localStorage` 에 남으므로 브라우저를 닫아도
유지됩니다. 켜면 탭 두 개가 더 붙습니다.

> Shift 는 대문자를 칠 때 누르는 키라, 다섯 번을 세는 것만으로는 `HELLO` 를 타이핑하는
> 것과 구분되지 않습니다. 그래서 **Shift 가 아닌 키가 하나라도 끼면 카운트가 0 으로
> 돌아가고**, 누르고 있어 생기는 자동 반복도 세지 않습니다 (`src/state/debugGesture.ts`).

**인터페이스** — 키보드가 노출하는 HID 인터페이스 전부와 설정 채널 후보 점수, 그리고
열 인터페이스를 직접 고르는 곳. 연결이 알아서 가장 높은 점수를 고르므로 평소엔 볼 일이
없고, 보드가 예상 밖의 VID 를 물고 나올 때 쓰는 탈출구입니다.

**디버그** — 최상단에 실시간 모니터링이 고정되고(도구를 옮겨도 스트림이 보입니다),
그 아래 분석 패널과 **키 식별 폴백 스위치**, 그리고 도구가 서브탭으로 들어갑니다.

(`src/protocol/codec.ts`)을 직접 구현해 같은 방식으로 등록합니다.

## 다른 키보드 대응하기

이 앱이 아는 것은 *보드 하나*가 아니라 **프로토콜 계열 하나**입니다 — 64바이트 벤더
프레임, 블록 전송, 8바이트 키별 성능 레코드, 3바이트 키맵 레코드. 보드마다 다른 것
— USB ID, 명령 번호, 블록 크기, 비트 위치, 키 배열, 스위치 목록 — 은 전부 데이터이고
`DeviceSpec` 한 값에 들어갑니다.

같은 계열의 다른 키보드를 지원하는 일은 **정의 파일 하나를 추가하고 빌드하는 것**이
전부입니다. `src/protocol/` 과 `src/features/` 는 손대지 않습니다.

- **TypeScript**: `src/device/boards/<board>/` 폴더를 만들고 `index.ts`(정의)·
  `layout.json`+`layout.ts`(키 표)·`switches.json`+`switches.ts`(스위치 표)·
  필요하면 `protocol.ts`(프로토콜)를 넣은 뒤
  `src/device/boards/index.ts` 의 `BUILT_IN_SPECS` 에 넣습니다. 타입 검사를 받습니다.
- **JSON**: `src/device/user/<board>.device.json` 에 같은 모양으로 씁니다. 빌드 때
  번들에 포함되고, 시작할 때 검사한 뒤 등록됩니다. 검사에 걸린 파일은 콘솔에 이유가
  찍히고 그 파일만 건너뜁니다.

적지 않은 항목은 Raven61 값을 물려받습니다(항목 단위로). 반드시 직접 적어야 하는
것은 `id` · `name` · `confidence` · `basedOn` · `usb` · `layout` 뿐입니다. 확인하지
못한 명령은 추측해서 넣지 말고 `null` 로 두세요 — 그 기능은 코덱에서 아예 빠지고,
패널이 "이 보드는 지원하지 않음"이라고 말합니다.

### 프로토콜은 공유된다고 가정하지 않습니다

해독된 프로토콜은 **한 대의 보드에서 확인한 하나**뿐입니다. 같은 벤더의 다른 모델이
같은 바이트에 답한다는 증거는 없으므로, 이 앱은 그렇게 가정하지 않습니다.

- **PID 는 정확히 일치해야 합니다.** 어떤 정의도 "이 벤더의 모든 제품"을 주장할 수
  없고(그런 옵션 자체가 없습니다), 목록에 없는 장치는 `unknownCodec` — 읽기·쓰기·
  아날로그 모드 전부 없음 — 을 받습니다. 패널은 "미해독" 상태가 되고, 키 그리드는
  가짜 배열을 그리는 대신 "이 장치의 정의가 없습니다" 와 VID:PID 를 보여 줍니다.
- **상속은 명시적인 주장입니다.** `basedOn: "raven61-v1"` 은 "이 보드가 그 프로토콜에
  답하는 것을 확인했다"는 선언이고, 없으면 정의가 거부됩니다. 이 값은 스펙에 그대로
  남아 누가 그렇게 주장했는지가 남습니다.
- Raven61 정의가 주장하는 PID 는 **`0xFED0` 하나뿐**입니다 — 펌웨어 이미지의 식별
  페이지가 스스로 보고하는 값(§2.10). 순정 드라이버에 있는 `0xFE20` · `0xFEB1` 은
  거의 확실히 Raven68 · ABT68 이고, 키 수도 프로토콜도 검증된 적이 없어 주장하지
  않습니다.

런타임 가져오기(업로드 버튼)는 없습니다. 정의 파일은 남의 키보드 플래시에 어떤
바이트가 쓰일지를 정하는 소스이므로, 소스 트리에 두고 빌드합니다.

보드 하나는 폴더 하나이고, 그 안에서 **`protocol.ts`(어떻게 말하는가)와
`index.ts`(무엇인가)** 가 분리돼 있습니다. 근거가 다른 두 가지라 한쪽만 공유할 수
있고, `src/device/protocols/default.ts` 가 바로 그 결과입니다 — Raven61 의 프로토콜만
복제한 기본값이고, 정체성은 들어 있지 않습니다.

### 아직 해독되지 않은 보드에 처음 말 걸기 (개발용)

정의가 없는 장치를 연결한 뒤 **인터페이스 패널**(Shift 5번으로 디버그 탭을 켭니다)에서
*기본 프로토콜로 강제 통신* 을 켜면, 정의 없는 장치에도 기본 프로토콜을 그대로 보내
응답을 볼 수 있습니다.

- ⚠ 보내는 건 **다른 키보드의 명령**입니다. 응답 없는 읽기는 손해가 없지만, 프로토콜이
  다른 하드웨어에 쓰기를 보내면 결과는 정의되지 않습니다(`0xa1` 은 설정 블록 전체
  쓰기입니다). 트래픽 로그를 열어 두고 읽기부터 하세요.
- 화면의 키 배열은 대체 표시이고 그 장치의 것이 아닙니다.
- 저장되지 않고 연결을 끊으면 해제됩니다. 매번 강제로 쓰는 건 지원이 아니라,
  정의를 쓸 만한 보드를 찾았다는 신호입니다.

자세한 절차와 각 필드를 무엇으로 확인해야 하는지는
[src/device/README.md](src/device/README.md) 에 있습니다.

## 다국어

화면에 보이는 문자열은 모두 `src/i18n/locales/*.json` 에 있습니다. 언어는 **상단 바**에서
(연결 전에는 연결 화면에서) 바꾸고, 저장된 값이 없으면 브라우저 언어를 따릅니다
(`navigator.languages`). 선택은 이 브라우저의 `localStorage` 에만 남습니다.

한국어(`ko.json`)가 기준 번들입니다. 키 목록은 이 파일에서 타입으로 뽑아내므로, 없는 키를
쓰면 컴파일이 실패하고, 번역에서 빠진 키는 한국어로 표시됩니다.

언어를 추가하려면:

1. `ko.json` 을 복사해 `src/i18n/locales/<코드>.json` 으로 두고 값만 번역합니다.
2. `src/i18n/index.ts` 의 `LOCALES` 에 한 줄, `BUNDLES` 에 한 줄 추가합니다.

번역문 안에서 쓸 수 있는 것:

- `{name}` — 코드에서 넘기는 값
- `<b>…</b>` `<i>…</i>` `<c>…</c>` — 굵게 · 기울임 · 고정폭(코드·경로·바이트값)
- `<키>_one` / `<키>_other` — 수가 1일 때와 그 밖일 때를 나누는 언어용. 한국어처럼 필요
  없으면 `<키>` 하나만 두면 됩니다.
