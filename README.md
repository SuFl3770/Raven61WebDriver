# Raven61 Web Driver

Raven61 홀 이펙트 키보드용 브라우저 기반 설정 도구입니다. WebHID로 보드에 직접 붙기
때문에 설치가 필요 없고, 순정 윈도우 드라이버 없이 크롬/엣지에서 바로 동작합니다.

> **브랜치:** 이 `dev` 브랜치는 **작업 중인 전부**입니다 — 리버스 엔지니어링 도구,
> 분석 스크립트, 아직 프로토콜이 해독되지 않은 설정 패널까지 포함합니다.
> `main` 은 완성되어 실제로 동작하는 것만 담습니다 (장치 연결 + 모니터).
> 기능이 완성되면 `dev` 에서 `main` 으로 올립니다.
> `main` 은 <https://sufl3770.github.io/Raven61WebDriver/> 에 자동 배포됩니다.
> 이 브랜치는 배포되지 않으므로 로컬에서 실행해야 합니다.

> **현재 상태:** **읽기는 하드웨어에서 검증 완료** — 입력 지점 탭이 61키 전부의 현재
> 설정을 보드에서 읽어 표시합니다. **액추에이션 포인트 쓰기는 하드웨어에서 확인
> 완료**, **래피드 트리거 쓰기도 붙었습니다** — 활성 · 민감도(누름/뗌) · 전체 스트로크
> 퀵 트리거 · 데드존은 키별 레코드로, "바닥까지 트리거"는 전역 블록으로 나갑니다.
> 어느 쪽이든 읽기-수정-쓰기로 보내고 쓴 뒤 다시 읽어 바이트를 대조합니다.
>
> 순정 드라이버 분석과 하드웨어로 확인된 것:
>
> - 장치 **VID `0x19F5`**, PID `FE20` / `FED0` / `FEB1`, USB 인터페이스 `MI_01`
> - 통신은 **OUTPUT / INPUT 리포트** (`WriteFile` / `ReadFile`), 65바이트, 리포트 ID 0
> - **패킷 프레임**: 매직 `0x55`, 명령, 합 체크섬. 쓰기 응답은 에코(`0xaa`),
>   **읽기 응답은 데이터를 실어 옵니다**
> - **송수신 헬퍼가 둘** — 읽기 명령은 전부 두 번째 쪽입니다 (§1.1)
> - **블록 전송**: 길이 + 오프셋(LE16) + 56바이트 청크. 읽기도 동일
> - **읽기 명령**: `0x05` 전역 설정 · `0x07` 키맵 · `0xa0` 키별 성능 · `0xde` RGB
> - **키별 성능 블록** 완전 해독 — 1024 B, 키당 8바이트. 동작 지점 · RT 활성 ·
>   RT 민감도 · 전체 스트로크 퀵 트리거 · 데드존 · 스위치 종류 (§4.5)
> - **쓰기(`0xa1`) 절차** 해독 — `0x01`, 56바이트 청크 19개, `0x02` (§4.5.5).
>   순정은 버퍼를 0으로 밀고 만들지만 이 앱은 읽기-수정-쓰기로 갑니다 (§4.5.6)
> - **전역 설정 쓰기(`0x06`)** — 순정도 `0x05` 응답을 복사해 고쳐 보냅니다 (§4.8.1).
>   이전 판의 "필드가 독립적이다" 는 근거 없는 서술이었고, 그 위에 만든
>   `enableAnalogReport` 가 폴링 레이트·데드존을 0으로 덮고 있었습니다
> - **필드 한계는 접힘이지 실패가 아니다** — 데드존 5비트(0.62 mm), 민감도·동작 지점
>   9비트. 인코더가 포화시키고 UI 상한도 같은 값을 씁니다 (§4.5)
> - **키 주소는 "슬롯"** — 계산할 수 없고 키맵 블록에서 받아야 합니다 (§4.6).
>   XML 의 `key_index` 는 순정도 쓰지 않는 사문이었습니다 (§6)
> - **`switch_type` 8종**과 스위치별 총 스트로크 — 총 스트로크는 4 mm 고정이 아닙니다 (§4.7)
> - **아날로그 키 이벤트** 완전 해독 — 61키 전부 식별, 실시간 모니터가 동작합니다
> - **보정 표를 펌웨어에서 읽어냈습니다 (§3.3)** — 키별 8바이트, 플래시 `0x20300`,
>   **`0xaa` 로 통째로 읽힙니다**. 실체는 float32 **보정 계수** 하나이고, 깊이 보고가
>   전부 이 값을 거칩니다. 이벤트에도 매번 실려 옵니다 — `payload[10]` 이 LED 색을
>   정하는 상태 바이트, `payload[11..13]` 이 계수의 10진 세 자리입니다
> - ⚠ **보드의 LED 는 보정 품질을 나타내지 않습니다** — 그 상태 바이트는 계수가 몇 번
>   커졌는지 센 값이라 펌웨어 업데이트 직후엔 멀쩡한 키까지 전부 빨강이고, 얕게 두 번만
>   눌러도 초록이 됩니다. 이 앱은 **계수**로 판정하고 보드의 판정은 나란히 보여 주기만
>   합니다 (§3.3)
> - 이 결론 전까지 이 프로젝트는 순정 드라이버만 보고 "판정 = ADC 진폭 누적 최댓값" 이라고
>   적고 있었습니다. **틀렸습니다** — 순정은 계산하지 않고 펌웨어가 준 바이트를 옮길
>   뿐입니다 (findings.md 오류 #19)
> - 스트림은 **켜야 흐릅니다** — `0xa8` 이 보고를 켜고(걸쇠) 동시에 테스트 모드에
>   들어가므로, 바로 `0xa9` 로 모드만 빠져나오면 **깊이 수신 + 타이핑 정상**입니다.
>   `0xa8` 을 **반복**하면 모드가 유지되어 캘리브레이션이 됩니다 (§3.2)
> - 값 인코딩 **1 카운트 = 0.02 mm**. 와이어는 **−1 오프셋**으로 저장
> - 설정 데이터 모델, 레이어 4개, 프로파일 3개, 고급 키 6종
> - ⚠ **`0xee` 는 공장 초기화**입니다. 스윕에 넣지 마세요 (§3)
>
> 자세한 내용은 [docs/protocol.md](docs/protocol.md), 무엇이 틀렸었는지는
> [docs/findings.md](docs/findings.md).

## 실행

```bash
npm install
npm run dev
```

크롬, 엣지, 오페라 **데스크톱** 에서 열어야 합니다 (WebHID 필요). 파이어폭스와 사파리는
WebHID를 지원하지 않습니다.

## 탭 구성

**첫 화면** — 장치가 붙기 전에는 연결 화면 하나뿐입니다. 나머지 탭은 전부 보드를
들여다보는 화면이라, 연결된 뒤에 나타납니다. 연결은 VID 0x19F5 프리셋으로 고르고
점수가 가장 높은 인터페이스를 자동으로 엽니다. 한 번 허용한 장치는 브라우저가
기억하므로 다음부턴 버튼 하나로 다시 붙습니다.

**설정 패널** — 입력 지점(읽기 + 쓰기) · 센서(모니터) · 캘리브레이션이 동작합니다.
키맵과 고급 키는 프로토콜 미해독이라 잠겨 있습니다.

| 탭 | 내용 |
|----|------|
| 입력 지점 | **동작** — 61키 전부의 현재 설정(동작 지점·RT·민감도·전체 스트로크·스위치 종류)을 보드에서 읽어 표시하고, **스위치 종류 · 동작 지점 · 래피드 트리거 · 데드존 · 바닥까지 트리거를 보드에 씁니다**. 쓴 뒤 다시 읽어 대조하고, 직전 1024바이트로 되돌릴 수 있습니다. 원본 블록 덤프 포함 |
| 센서 | **동작** — 실시간 키 깊이, 트레이스, 키별 원시 ADC |
| 키맵 | Main + FN 1–3, 총 4레이어 키코드 배정 |
| 설정 | **동작** — 펌웨어 빌드 정보, 폴링 레이트·디바운스 읽기·쓰기, 공장 초기화(⚠ 확인 2단계) |

**디버그 모드** — **Shift 를 5번 빠르게** 누르면 켜지고, 같은 동작으로 꺼집니다. 화면에
버튼은 없습니다 — 프로토콜을 해독할 때 말고는 쓸 일이 없는 기능이라 눈에 보이는 자리를
차지하지 않게 했습니다. 켜짐 여부는 `localStorage` 에 남으므로 브라우저를 닫아도
유지됩니다. 켜면 탭 두 개가 더 붙습니다.

> Shift 는 대문자를 칠 때 누르는 키라, 다섯 번을 세는 것만으로는 `HELLO` 를 타이핑하는
> 것과 구분되지 않습니다. 그래서 **Shift 가 아닌 키가 하나라도 끼면 카운트가 0 으로
> 돌아가고**, 누르고 있어 생기는 자동 반복도 세지 않습니다 (`src/state/debugGesture.ts`).

**인터페이스** — 키보드가 노출하는 HID 인터페이스 전부와 설정 채널 후보 점수, 그리고
열 인터페이스를 직접 고르는 곳. 연결이 알아서 가장 높은 점수를 고르므로 평소엔 볼 일이
없고, 보드가 예상 밖의 VID 를 물고 나올 때 쓰는 탈출구입니다.

**디버그** — 최상단에 실시간 모니터링이 고정되고(도구를 옮겨도 스트림이 보입니다),
그 아래 분석 패널과 **키 식별 폴백 스위치**, 그리고 도구가 서브탭으로 들어갑니다.

| 서브탭 | 내용 |
|--------|------|
| 탐색기 | 리포트 디스크립터 트리, 사용 가능한 리포트 ID와 길이 |
| 콘솔 | 프레임/블록 형식으로 명령 송신, 반복 전송 후 변하는 바이트 표시 |
| 프로버 | 실제 프레임(체크섬 자동)으로 명령을 스윕하고 응답 확인 |
| 이벤트 | 보드가 올려보내는 리포트 수신 + 센서 주소 연결 (기본 수신 전용, 스트림 켜기는 선택) |
| 로그 | 모든 송수신 기록, A/B 바이트 diff, TXT·JSON 내보내기 |

분석 패널: 관측된 식별자, 키 주소 후보, 기준 ADC 표류.

## 프로토콜 작업

- 캡처 절차와 방법론: [docs/reverse-engineering.md](docs/reverse-engineering.md)
- 알아낸 내용 기록: [docs/protocol.md](docs/protocol.md)
- 추론 과정·증거 등급·틀렸던 결론: [docs/findings.md](docs/findings.md)
- 코덱 검사 (가짜 보드로 쓰기 경로 확인): `npm run check`
- 명령 표 추출 (정적 분석): `python tools/bin/commands.py "<순정 드라이버>/Raven Driver.exe"`
- 순정 DB 읽기/비교: `python tools/db/extract.py a.db --diff b.db`
- 런타임 추적: `frida -f "Raven Driver.exe" -l tools/frida/trace-hid.js`
- 캡처 변환/비교: `node tools/pcap/extract.mjs --diff a.pcapng b.pcapng`
- 레이아웃 재생성: `node tools/layout/from-vendor-xml.mjs "<순정 드라이버>/layouts/Raven61.xml"`

순정 드라이버 파일 자체는 재배포 대상이 아니므로 `.gitignore` 에 넣어 두었습니다.
로컬에 두고 위 생성기로만 참조합니다.

해독한 명령은 `src/protocol/` 에 `Raven61Codec` 구현으로 추가하고
`src/protocol/registry.ts` 의 `CODECS` 맨 앞에 등록하면 됩니다. 구현한 메서드만큼 UI가
자동으로 열립니다.

## 구조

```
src/
  hid/         WebHID 전송 계층 — 장치 핸들, 리포트 길이, 요청/응답 대응, 트래픽 로그
  protocol/    패킷 프레임, 이벤트 디코더, 코덱 인터페이스, 도메인 모델
  keyboard/    Raven61 61키 배열, HID 키코드 표, 수정자 지문 폴백
  i18n/        문자열 번들과 번역 함수 — UI 문자열은 전부 여기에만 있습니다
  state/       연결·설정·선택 스토어
  tools/       리버스 엔지니어링 UI
  features/    설정 UI
```

## 다국어

화면에 보이는 문자열은 모두 `src/i18n/locales/*.json` 에 있습니다. 언어는 **상단 바**에서
(연결 전에는 연결 화면에서) 바꾸고, 저장된 값이 없으면 브라우저 언어를 따릅니다
(`navigator.languages`). 선택은 이 브라우저의 `localStorage` 에만 남습니다.

한국어(`ko.json`)가 기준 번들입니다. 키 목록은 이 파일에서 타입으로 뽑아내므로, 없는 키를
쓰면 컴파일이 실패하고, 번역에서 빠진 키는 한국어로 표시됩니다.

언어를 추가하려면:

1. `ko.json` 을 복사해 `src/i18n/locales/<코드>.json` 으로 두고 값만 번역합니다.
2. `src/i18n/index.ts` 의 `LOCALES` 에 한 줄, `BUNDLES` 에 한 줄 추가합니다.

번역문 안에서 쓸 수 있는 것:

- `{name}` — 코드에서 넘기는 값
- `<b>…</b>` `<i>…</i>` `<c>…</c>` — 굵게 · 기울임 · 고정폭(코드·경로·바이트값)
- `<키>_one` / `<키>_other` — 수가 1일 때와 그 밖일 때를 나누는 언어용. 한국어처럼 필요
  없으면 `<키>` 하나만 두면 됩니다.

## 라이선스

Apache-2.0. 자기 소유 기기의 상호운용성 확보를 위한 프로젝트이며, 순정 드라이버의 코드나
바이너리는 포함하지 않습니다.
